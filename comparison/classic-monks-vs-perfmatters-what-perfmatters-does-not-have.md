# Classic Monks vs Perfmatters: What Perfmatters Doesn't Include

This **Classic Monks vs Perfmatters** comparison looks at what Classic Monks adds beyond Perfmatters, including security, WooCommerce, setup, media, staging, AI, and agency delivery.

We compared the official Perfmatters feature page and pricing page with the live Classic Monks feature and pricing pages, the current Classic Monks changelog, and the local feature references used to verify implementation scope. The comparison reflects the August 20, 2026 feature set.

**How we selected the differences:** We included a category when the current Perfmatters feature list does not represent a comparable workflow and Classic Monks has a documented, implemented capability. We kept material limitations visible where Perfmatters still owns a workflow or where the products take different approaches.

The better question is: **What can Classic Monks add to a WordPress site that is outside Perfmatters' current feature set?**

Perfmatters is a focused performance plugin, and it is excellent at that one job. Classic Monks is a modular WordPress stack that includes performance controls as one part of a much wider plugin: security, WooCommerce, media workflows, setup tools, staging protection, AI, admin utilities, and agency white label. The official Classic Monks features library currently lists **393+ features**, including **162 Bricks Builder tools**.

Perfmatters remains a strong specialist. It also owns workflows Classic Monks does not currently match, including Script Manager depth, JavaScript deferral and delay, unused CSS removal, minification, and scheduled database cleanup. This post focuses on the other side of the decision: the capabilities you gain when Classic Monks becomes your core WordPress stack.

> **Quick verdict:** Choose Classic Monks when you want one modular plugin to cover security, WooCommerce, setup, media, staging, AI, admin, and white-label delivery alongside performance controls. Keep Perfmatters, or run both during migration, when you depend on its deep front-end surgery, such as Script Manager granularity, JS defer and delay, unused CSS removal, or scheduled database cleanup.

## Does Classic Monks offer security features that Perfmatters does not?

Yes, and this is the largest category gap. Perfmatters changes the login URL and offers disable toggles for XML-RPC, the REST API, feeds, and a few other surfaces. It has no login lockdown, no 2FA, no CAPTCHA, no content protection, and no staging protection.

Classic Monks includes a full security tab with 39 per-feature docs:

* Custom login URL, login lockdown with extended lockout, Cloudflare Turnstile, and math CAPTCHA
* 2FA with TOTP authenticator app and email OTP, trusted devices, and 2FA rate limiting
* Auto logout, user-enumeration blocking, REST API and XML-RPC controls, and file-modification controls
* Email and phone protection, site-wide password protection, and AI crawler blocking
* Content protection for copying, selection, printing, and inspection
* Staging Protection with access tokens, HTTP authentication, and IP allowlists

For an agency, this changes the stack math. A Perfmatters site still needs a separate security plugin. A Classic Monks site has the security layer inside the same install. Read the [WordPress security documentation](https://classicmonks.com/docs/security/) for the current list.

Perfmatters offers useful WooCommerce performance toggles: disable cart fragments, disable WooCommerce scripts and styles on non-store pages, and disable WooCommerce widgets. Those are performance controls, not store features.

Classic Monks includes a dedicated WooCommerce tab with 50 per-feature docs across 11 subtabs:

* Product swatches for colors, images, and labels
* Checkout field cleanup, placeholders, inline validation, and custom order headings
* Direct checkout links and a checkout product selector
* URL coupons, automatic coupon application, BOGO deals, and role-based restrictions
* Custom order statuses, order-table columns, and product price history
* Redirects for cart, login, logout, and My Account workflows
* WooCommerce script and style controls on non-store pages, plus cart-fragmentation controls
* Store email controls

Perfmatters can help a store load faster. Classic Monks also runs the store. For an agency building WooCommerce sites, that difference removes a separate collection of store extensions. Read the [WooCommerce documentation](https://classicmonks.com/docs/woocommerce/) for the current store feature set.

## How does Classic Monks improve a new WordPress setup?

Perfmatters is configured on an existing site. It has no setup workflow, because provisioning is outside its scope.

Classic Monks includes Quick WordPress Setup, a guided wizard for fresh WordPress installations. It handles site identity, plugin and theme selection, homepage settings, cleanup of default content, and environment configuration in about 2 to 3 minutes. It also includes a separate Bricks setup workflow for importing Bricks theme styles, global settings, and templates.

That matters when an agency repeats the same baseline work across client sites. Instead of installing several utility plugins and rebuilding the same starting checklist, the team begins with one setup workflow and enables only the features needed for that project.

Quick WordPress Setup is a feature for provisioning a real WordPress site. Read the [Quick WordPress Setup guide](https://classicmonks.com/docs/quick-wp-setup/) for the workflow and prerequisites. It is not the Classic Monks demo sandbox. If you want to try the plugin without changing an existing site, use the [Classic Monks demo](https://classicmonks.com/demo/).

## What does Perfmatters still own that Classic Monks does not?

This is where the comparison stays honest. Perfmatters is the deeper front-end optimization tool, and its Script Manager is the reason.

* **Script Manager depth.** Disable scripts per post or page, per device, and per login state. Scripts are grouped by plugin and theme. Regex rules target combinations of scripts. MU mode disables a plugin's front-end scripts, inline code, and MySQL queries entirely. Testing Mode previews the configuration before it reaches the public site. Classic Monks has an Assets Manager that conditionally disables scripts and styles per page, but nothing with this level of per-device, per-state, or regex control.

* **Defer and delay JavaScript.** Add defer tags, defer inline JavaScript, and delay scripts until user interaction, with exclusions per file and per page. Classic Monks does not defer or delay global JavaScript.

* **Remove unused CSS.** Two methods (file and inline), three behaviors for the original stylesheet, and selector or per-page exclusions. Classic Monks has no remove-unused-CSS feature.

* **Minify JS and CSS.** Global minification with exclusions. Classic Monks minifies Bricks styles but not global JavaScript or CSS.

* **Scheduled database cleanup.** Delete revisions, auto-drafts, spam, trash, and expired transients, optimize tables, and schedule it daily, weekly, or monthly. Classic Monks limits revisions and configures autosave but does not schedule routine cleanup.

* **Local Google Analytics and Google Fonts.** Host both locally to remove third-party DNS lookups. Classic Monks can disable Google Fonts but does not host them locally.

* **Preload depth.** DNS prefetch, preconnect, fetch priority, Early Hints, and speculative loading for hover pre-rendering. Classic Monks preloads critical images and predicts navigation with Monks Preloading, but does not expose this full control set.

* **Performance-specific extras.** YouTube preview thumbnails for lazy-loaded iframes, DOM monitoring, CLS fixing via added width and height attributes, WP-CLI support, and 135+ step-by-step docs.

One boundary applies to both products: **neither Classic Monks nor Perfmatters is a full-page caching plugin.** Classic Monks includes asset controls, lazy loading, preloading, and CDN rewrite, but it does not claim full-page caching. Perfmatters officially describes itself as designed to work alongside your caching plugin. Keep the caching layer the site needs either way.

## Should you switch from Perfmatters to Classic Monks?

Use this decision rule:

* **Choose Classic Monks** if you manage client sites and want one modular core stack for security, WooCommerce, performance, setup, media, AI, staging, admin, and agency delivery.
* **Keep Perfmatters** if performance is the only job and you want the deepest script and asset control available, especially JS deferral and delay, unused CSS, minification, and scheduled database cleanup.
* **Use both during migration** if Classic Monks covers most of your stack but one or two Perfmatters optimizations remain necessary. Disable overlapping modules so one plugin owns each concern.

Migration is partial in both directions, so do it on staging:

1. List every Perfmatters toggle you have enabled, per site.
2. Map the overlapping controls to Classic Monks: emojis, Dashicons, embeds, feeds, XML-RPC, REST API, Google Fonts, Google Maps, jQuery Migrate, revisions, autosave, Heartbeat, login URL, lazy loading, and CDN rewrite.
3. Enable one Classic Monks replacement at a time on staging.
4. Keep Perfmatters active for the gaps: JS defer and delay, unused CSS, minification, database cleanup, local analytics and fonts, and per-device script control.
5. Take a full-site backup, then test login, checkout, forms, and front-end output on staging.
6. Clear caches, compare speed scores, and keep Perfmatters on the live site until the Classic Monks configuration soaks for a few days.

## Frequently Asked Questions

### Is Classic Monks better than Perfmatters?

Classic Monks is better for agencies and WordPress professionals who need a broader stack covering security, WooCommerce, setup, media, staging, AI, admin, and white-label delivery. Perfmatters is better for the focused performance job, especially Script Manager depth, JS defer and delay, unused CSS, minification, and database cleanup.

### Can Classic Monks replace Perfmatters?

Partially. Classic Monks covers the same class of quick toggles, lazy loading, CDN rewrite, and code snippets, plus the whole WordPress stack beyond performance. It does not match Perfmatters' Script Manager depth, JS defer and delay, unused CSS removal, global minification, or scheduled database cleanup. If those matter, keep Perfmatters.

### Does Classic Monks have a Script Manager like Perfmatters?

Classic Monks has an Assets Manager that conditionally disables scripts and styles per page and shows non-loaded assets. It does not have Perfmatters' per-device, per-login-state, regex, or MU-mode control. That depth is Perfmatters' territory.

### Is Classic Monks a caching plugin?

No. Classic Monks has asset controls, lazy loading, preloading, and CDN rewrite, but it does not claim full-page caching. Perfmatters is not a caching plugin either. Keep the caching layer the site needs.

### Can I use Classic Monks and Perfmatters together?

Yes. Assign one owner per shared concern: lazy loading, CDN rewrite, asset disabling, script control, and snippets. A common setup is a cache plugin, Classic Monks for the stack, and Perfmatters where its specific optimizations are needed.

### Does Perfmatters have security or WooCommerce features?

Perfmatters changes the login URL and offers WooCommerce performance toggles like disabling cart fragments. It has no login lockdown, 2FA, CAPTCHA, staging protection, content protection, or store operations. Those are Classic Monks Security and WooCommerce territory.

### Which is cheaper for an agency: Classic Monks or Perfmatters?

Perfmatters renews yearly: $59.95 for three sites or $124.95 for unlimited sites, with a 15% renewal discount. Classic Monks Agency is $299 one-time for 100 sites and includes security, WooCommerce, setup, media, and white-label features Perfmatters does not have. Compare scope, not only price.
