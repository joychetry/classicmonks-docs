## Coexistence guidance

Running Classic Monks and WP Extended together is a valid migration path. The rule is simple: assign one plugin as the owner of each shared concern.

- **SMTP:** Keep one SMTP configuration. Disable the other.
- **Login lockdown and security:** Choose one Limit Login Attempts, one Custom Login URL, and one XML-RPC control.
- **Code snippets:** Classic Monks Code Manager or WP Extended Code Snippets. Pick one.
- **Media replacement:** One plugin handles media replacement. Not both.
- **Admin menus:** One plugin controls admin menu visibility. Not both.
- **Maintenance mode:** Choose one maintenance mode implementation.

Overlapping modules can produce confusing output, duplicate settings screens, or unexpected behavior. Disable the WP Extended module when Classic Monks owns the concern, and test each change on staging before touching production.

## Migration checklist (staging-first)

1. Inventory your enabled WP Extended modules on the live site. Note which ones the site actually uses, not just which are installed.
2. Take a real full-site backup.
3. Install Classic Monks on staging.
4. Enable one Classic Monks replacement feature at a time.
5. Test login, roles, frontend output, forms, email, redirects, WooCommerce checkout (if applicable), Bricks editing (if applicable), and cache behavior as relevant.
6. Disable the overlapping WP Extended module one at a time.
7. Assign one plugin ownership for SMTP, login lockdown, code snippets, media replacement, admin menus, and any security controls.
8. Clear caches and retest.
9. Keep unresolved WP Extended modules until the site's soak period passes (minimum one week for staging, two weeks for production).
10. Remove only genuinely redundant tools.

## Frequently asked questions

### Is Classic Monks a good WP Extended alternative?

Classic Monks is better for agencies and WordPress professionals who need a broader stack covering AI, Bricks, WooCommerce, performance, media, staging, setup, and white-label delivery. WP Extended is still better for some focused workflows, especially Quick Search, Quick Post, its Rollback Manager, export tools, and the Pixel Tag Manager.

### Can Classic Monks replace WP Extended?

It can replace many WP Extended modules, but not all of them. Compare the enabled modules on the site, not only the installed plugin. Test the Classic Monks equivalent on staging before disabling WP Extended.

### Can I use Classic Monks and WP Extended together?

Yes. This is a sensible migration path. Assign one owner for shared concerns such as SMTP, login lockdown, code snippets, admin menus, and media replacement. Duplicate ownership can create conflicts and confusing output.

### Does Classic Monks replace WordPress caching plugins?

Not completely. Classic Monks includes asset controls, lazy loading, preloading, image conversion, and related performance tools. It does not claim to be a full-page caching product. Keep the caching layer the site needs.

### Why is WP Extended cheaper for one site?

WP Extended's entry plan is $29/year while Classic Monks starts at $39/year. The price difference reflects scope. WP Extended focuses on utility modules. Classic Monks includes AI, Bricks, WooCommerce, performance operations, staging protection, and agency tools. For one site with basic admin needs, WP Extended is the more affordable choice. For a site that needs the broader stack, Classic Monks covers more ground per dollar.

### What is the fastest way to test Classic Monks?

Use a staging site or the [Classic Monks demo](https://classicmonks.com/demo/). On a fresh WordPress installation, [Quick WordPress Setup](https://classicmonks.com/docs/quick-wp-setup/) can handle the initial site configuration before you enable the features relevant to the project.
